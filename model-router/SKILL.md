# 模型路由（Flash / Pro）v4.4

## 版本变化（2026-08-14）
- v3：Codex 桌面端已可手动切换 Flash/Pro（用户实测确认）。手动切换成为 Pro 执行首选通道；API 直调降级为兜底。
- v4：加入「切换纪律」——一次任务链最多切换一次、切换只发生在任务起点或交付后、中途升级必须先写状态交接块、完成 ≥70% 不中途抢救。
- v4.1：加入「子任务级路由」——大任务按交付物边界拆子任务、各自判定一次、Pro 累计切换 ≤2 次，把“拆任务后按小问题选模型”的想法规则化。
- v4.2：按 2026-08-14 实测修正——拆分不省钱（C≈1.9×B、D≈2.6×B），改为“默认不拆，仅大型多交付物才拆”；长分镜/长剧本批量产出回到 Pro 清单直接触发（修复判定漏判）。
- v4.3：按第 2 版实测（思考模式+真实任务）修正——①大输出批量任务拆路由反超全 Pro（覆盖 0.86 vs 0.67、成本 0.089 vs 0.114），拆不拆看输出规模；②创作任务按“量级清单”直接判定，不靠评分表（同一任务 Flash 评分两轮 20↔45 漂移）；③网文长文（>3K 字/跨多章）入 Pro 清单。
- v4.4：按第 3 版大样本实测（13 任务×2 轮、104 调用、1.60 元）定案——①判定 13/13 且边界评分两轮稳定，量级清单与 Pro 清单定案；②全 Pro 成本 2.9×Flash、质量仅在最难创作任务 +0.5~1 分，默认 Flash 维持；③重任务拆路由覆盖 0.94 vs 全 Pro 0.60–0.80、耗时更短，“大输出才拆”验证成立；④长输出任务（60 镜级）思考模式会吃光预算返回空，长输出关思考、空输出自动兜底重跑。

## 适用范围
- 只有主对话（根代理）执行路由。Pro/Flash 任务直接干活，禁止再次路由（防无限嵌套）。
- 用户手动指定模型（界面切换，或说“用 Pro/用 Flash”）时，听用户的，本轮不判定；下一轮新任务恢复自动判定。

## 判定时机
- 每个新任务或任务目标变化时，判定一次。
- 同一任务链内的追问、修改、返修沿用首次判定，不反复切换模型。
- 信息不足时先做轻量侦察（读文件、列影响面，Flash 成本极低），再判定；不盲判。

## 切换纪律（性能防护，v4）

总原则：一次任务链最多切换一次；切换只发生在任务边界（执行前 / 交付后）；用户手动指定永远最大。

1. 判定先行，执行在后：判定需要 Pro 时，在动手前提示“建议上 Pro，界面切一下”，等用户切换或确认；不提前开始正式执行。
2. 一次任务链只切一次：同一任务链（含追问、修改、返修）沿用首次判定，禁止来回横跳；用户手动强制切换后，本任务链锁定为该模型直到交付。
3. 中途升级唯一合法路径＝状态交接：仅“边界任务”（先交大纲/小样/前几镜再判断）允许先小样后升级；升级前必须给 Pro 写交接块（见第 7 条），没有交接块不许中途升级。
4. 70% 红线：任务已完成约 70% 才发现该用 Pro → 不切，先以当前模型交付；返工作为新的任务链再上 Pro。例外：质量风险极高且改动尚未落盘，才允许按第 3 条交接升级。
5. 交付后再切回：Pro 任务交付并验收后才提示切回 Flash；验收过程中不提示，避免验收标准漂移。新任务到达时若用户仍停在 Pro，按当前模型执行，不主动劝回。
6. 用户手动切换 > 一切：用户说“用 Pro/用 Flash”或界面切换，立即生效，本任务链不再自动判定/建议。
7. 交接块格式（≤6 行，写在下一条消息开头）：
   - 目标：…
   - 已完成：…
   - 未完成/卡点：…
   - 下一步：…
   - 验收标准：…
8. 不切场景白名单：简单问答、单文件小改、查资料、日常整理、生成总结、自动化/心跳任务；同一主题连续小追问（<3 轮）不切。
9. 预算与防空：Pro 长文/文档任务，界面下分批交付并说明“内容较长，我会分段写”；API 兜底 max_tokens ≥32768；content 空且 finish_reason=length → 加大预算重试 1 次。

## 子任务级路由（v4.1）

总原则（2026-08-14 两版实测后修订）：拆不拆看输出规模。小任务/短输出拆了更贵（第 1 版：C≈1.9×B）；大输出批量任务拆了更省且更好（第 2 版：C 覆盖 0.86 vs 全 Pro 0.67、成本 0.089 vs 0.114）。

1. 默认不拆：先按总任务一次性判定（沿用「判定方法」）；小任务/短输出（预计输出 <3K token）永远不拆。
2. 只有同时满足才拆：① 多个独立交付物（各有文件/验收标准、可单独返工）；② 预计总输出 >10K token 或 Pro 输出 >5K token。两条缺一不拆。
3. 拆法：按交付物边界拆，不按小问题碎切；同一交付物内部禁止再拆。
4. 每个子任务开始时独立判定一次，判定只作用于该子任务；总任务内 Pro 累计切换 ≤2 次（Flash → Pro → Flash），超出则合并成一次 Pro 跑完。
5. 成本红线：子任务共享大上下文（约 >50K）时不拆，按总任务一次性判定。真实聊天有前缀缓存，切换成本低于 API 全量重发，但延迟与状态风险仍在。
6. 数据依据：见 [references/experiment-2026-08-14.md](references/experiment-2026-08-14.md)——第 1 版（小任务）：C≈1.9×B、D≈2.6×B；第 2 版（真实任务+思考）：C 覆盖 0.86 vs 全 Pro 0.67；第 3 版（13 任务×2 轮）：判定 13/13 稳定、C 重任务覆盖 0.94 vs 全 Pro 0.60–0.80、全 Pro 2.9×Flash。

## 判定方法（顺序执行）
1. 用户显式指定 / 已在界面切换 → 按当前模型直接执行，跳过后续判定。
2. 命中 Pro 清单任一项 → 建议 Pro：
   - 仓库级/跨模块重构（牵一发动全身、依赖关系不清）；
   - 高难度编码或疑难 bug（跨文件深链路、性能/并发/安全类）；
   - 核心架构、算法设计（长链推理）；
   - 复杂多步 Agent 任务（自动化、安全、终端操作，完成率要求高）。
   - 长分镜/长剧本批量产出（>50 镜或跨多集；≤20 镜单集按边界任务规则先 Flash 小样）。
   - 网文长文（>3K 字，或跨多章/全文一致性修订）。
3. 创作类任务按量级清单直接判定（不靠评分表）：
   - 短剧分镜 ≤20 镜/单集 → Flash 先出小样；质量不达标再升 Pro。
   - 网文单章正文 ≤2K 字 → Flash；长文/多章/全文一致性修订 → Pro（命中上一条清单）。
   - 整理、总结、问答、拆解素材 → Flash。
4. 未命中清单 → 按返工风险评分（可叠加），≥30 → 建议 Pro；<30 → Flash：
   - 改动跨 3+ 文件/模块且依赖关系不明：+30（单项即可触发）
   - 无法快速本地验证（无测试/无法运行/结果难自查）：+25
   - 一次交付（对外/生产/质量要求高）：+20
   - 逻辑链长（多步骤/多条件/状态多）：+20
   - 结构清晰、可迭代、影响面小：0（Flash）
5. 边界任务（长分镜/长剧本、多文件但结构清晰）：不整篇盲写，先交付大纲/小样/前几镜快速判断；质量不达标则按「切换纪律」第 3、7 条交接后升 Pro 返工该部分（同一任务链延续，不重新判定）。若评分已 ≥30，直接建议 Pro。注意：Flash 对同一边界任务的评分会漂移（实测两轮 20↔45），边界任务优先用“小样验证”而非打分。

## Pro 执行序列（v4）
1. Flash 判定需要 Pro → 按「切换纪律」：在动手前一句话说明（“这个任务建议上 Pro，界面切一下”），等用户切换或确认；不擅自 API 直调。
2. 用户切到 Pro（界面）→ 当前对话直接按 Pro 执行，本序列其余步骤只做预算与验收：
   - 文档/长文类任务给足输出预算：界面无 max_tokens 参数时，长内容分批交付并说明“内容较长，我会分段写”；API 通道 max_tokens ≥32768 或非思考模式。
3. 用户不切换但明确让继续 → 兜底走 API 直调 deepseek-v4-pro + Flash 落地并验证（打包上下文 → 调用 → 验收 → 不合格返修最多 1 次 → 仍不合格给选项）。
4. 空内容兜底：API 直调时 content 为空且 finish_reason=length（思考吃满预算）→ 加大 max_tokens（≥32768）重试 1 次。
5. 交付后：若用户仍停在 Pro，提示“这个任务结束了，可以切回 Flash”，不强制；下一次新任务重新判定。
6. 用户打断：先响应用户，再决定继续/取消当前 Pro 任务。
7. 长输出防空（v4.4 实测）：预计输出很长（60 镜级、3K+ 字正文）时默认关思考模式；思考模式返回空内容时，自动用关思考模式兜底重跑一次。

## 执行通道（2026-08-14 结论版）
- 首选：Codex 桌面端界面手动切换（用户实测可用，最稳，无子代理通道问题）。
- 兜底：API 直调 deepseek-v4-pro + Flash 验收（用户不愿切换但任务确实重时）。
- 子代理通道仍不可用：spawn_agent / followup_task 在 DeepSeek（非 OpenAI）下任务正文被 encrypted_content 丢弃（上游 openai/codex #37237 / #36493 / #37822）；若上游修复或探针通过，恢复 spawn_agent 首选并重新实测。

## 透明度与纠偏
- 建议上 Pro 时用一句话说明（“这个任务建议上 Pro，界面切一下”）；Flash 任务不播报判定。
- 判定错误：用户直接在界面切模型即可强制纠正，下一任务恢复自动判定。
