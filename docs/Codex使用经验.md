# Codex 使用经验（通用版）

以下经验来自长时间真实使用，不含个人环境信息，可直接分享给其他 Codex 用户。

## 1. 先懂三件事

1. Codex 是“规则驱动”的：`AGENTS.md` 是契约，重要规则写进去，它每次自动读。
2. 重要结论必须落盘：长对话会被压缩，结论写进文件/技能/日志才可靠。
3. 技能（Skills）= 说明书：一个技能就是一个含 `SKILL.md` 的文件夹，触发靠 description，放到 `~/.codex/skills`（或 junction）后重启生效。

## 2. 第三方模型配置

- 在 `config.toml` 配置 `model_provider`、`base_url`、`wire_api = "responses"`，API key 放 `experimental_bearer_token`，不要到处贴 key。
- 自定义 `models.json` 让模型选择器显示你的模型；改配置要完全重启才生效。
- 非 OpenAI 提供方（如 DeepSeek）下，子代理消息通道存在上游 bug（任务正文被 `encrypted_content` 丢弃）：表现为子代理“收不到任务”。对策：重活用 API 直调 Pro 模型 + Flash 验收。
- 沙箱默认只能写工作区；写别处要提权；直连 API 偶发 TLS 断连，提权后正常。

## 3. 工具与文件操作

- `apply_patch` 抽风时备好 `patch-apply.ps1`（精确替换、UTF-8 无 BOM）。
- 注意：patch-apply 走 `powershell -File` 时参数里的英文双引号会被吃掉；改 JSON/含引号代码用 .NET `Replace` + 改后校验。
- 中文路径/中文脚本喂给 `python -` 会乱码：先写成 UTF-8 临时文件再执行。
- 大操作（迁移软件、改配置）先备份 → 操作 → 校验 → 保留回滚副本 → 确认后再删。

## 4. 写规则和输出

- 长文本输出前先读必读文件，输出开头写“必读文件已核对：xxx”。
- 输出前五步检查（复述需求→查逻辑缺口→独立判断→核实数字→指出异议）非常有效。
- 规则只放一份，禁止复制进多个项目，避免版本漂移。
- 经验要沉淀：单次教训记日志，能跨任务复用的才升级成技能/规则。

## 5. 省钱模型路由

- 日常用便宜模型（Flash），重活才上贵模型（Pro），先判定再执行：命中“跨模块重构/疑难 bug/复杂架构/多步任务”或返工风险评分 ≥30 才上 Pro。
- Pro 文档任务给足输出预算（max_tokens ≥32768）；空输出且 `finish_reason=length` = 思考吃满预算，加大预算重试一次。
- 保持 AGENTS/技能文件稳定能提高前缀缓存命中率（省 token）；贵模型约为便宜模型 3 倍价格，且官方可能推出高峰翻倍定价。

## 6. 防崩与心态

- 遇到诡异问题：读日志 → 查 GitHub issues（很多“我的错”其实是上游 bug）→ 重启 → 回滚备份。
- 自动化要做成幂等（已处理的不重复），否则每天重复跑。
- 删东西前确认路径，能用回收站/改名保留就别永久删。

**三句话**：把规则写进 AGENTS.md；重要结论落盘不靠对话记忆；遇到怪问题先查 GitHub issues 和重启。
